# Серверное подключение модели OpenDesign

## Прямой OpenAI-совместимый API

Штатный OpenCode можно подключить напрямую, без AI Hub. Оператор сохраняет
приватный `pdlc-inference.json` в разрешённом корне данных daemon:

```json
{
  "transport": "openai-compatible",
  "baseUrl": "https://gateway.example/v1",
  "model": "main-dev",
  "key": "<private-inference-key>"
}
```

Этот файл имеет приоритет над прежним `pdlc-ai-hub.json`. Некорректный новый файл
останавливает запуск, без скрытого переключения на прежний маршрут. Для внешнего
адреса требуется HTTPS. Для явно выбранного частного IPv4 API оператор может
добавить `allowInsecurePrivateHttp: true`; это не разрешает публичный HTTP.
Ключ остаётся на сервере и передаётся только настроенному API; redirects запрещены.
Он не включается в публичный config, payload запуска, образ или браузер.

Если сеть контейнеров пересекается с LAN-подсетью API, можно указать необязательный
`proxyUrl` в том же приватном файле. Это origin доверенного HTTP/HTTPS-proxy без
credentials, пути, query и fragment. Для Docker Desktop используется уже
работающий системный proxy `http://http.docker.internal:3128`; новый сервис и
правила в сетевом namespace Docker не требуются. Эта настройка применяется только
к проверке каталога и запросам managed OpenCode к модели. Central Auth, Tracker
и локальные инструменты сохраняют прежнее подключение. Без `proxyUrl` поведение
не меняется. Перед установкой проверить proxy из контейнера и сохранить прежнюю
конфигурацию; перезапускать только OpenDesign штатным оператором.

После замены файла перезапускают только OpenDesign существующим оператором.
`GET /api/pdlc/inference/status`, кнопка проверки и `od status --json` проверяют
каталог `/models` этого API без генерации. И основной OpenCode, и его служебные
запросы используют выбранный `main-dev`. Автоматический перезапуск CLI для такой
серверной конфигурации отключён; ключ идемпотентности полезен только если провайдер
сам поддерживает этот контракт. Проверенный каталог не гарантирует успешную генерацию.
Central Auth, Tracker и файлы студии сохраняют прежнее поведение.

Для возврата к прежнему Hub-маршруту удаляют новый файл и перезапускают OpenDesign.
Перед изменением сохраняют приватную копию конфигурации и резервную копию данных.

## Подключение через AI Hub

OpenDesign сохраняет штатный OpenCode runtime, его инструменты, создание файлов
и поток событий. В PDLC оператор может направить OpenCode через один опубликованный
профиль Hub. Центральная авторизация защищает студию; отдельный Hub client key
разрешает inference и не заменяет пользовательскую сессию.

## Настройка установки

Daemon читает приватный `pdlc-ai-hub.json` из уже разрешённого корня данных,
по той же схеме, что существующие integration configs. Поля: `origin` (origin Hub,
HTTPS либо явно заданный локальный installation origin), `model` (опубликованный
virtual model slug, для этой установки согласован `main-dev`) и `key` (отдельный
ключ клиента `open-design`). Ключ не включают в образ, Git, публичный config или
browser storage. Отсутствующий файл сохраняет обычный runtime; неполный или
некорректный файл останавливает запуск. Новых переменных installation bundle нет.

Расположение данных определяется [контрактом daemon](../AGENTS.md#daemon-data-directory-contract).
Файл должен сохранять приватные права; резервная копия с ним является секретной.
Ротация ключа: выпустить новый ключ, заменить приватный файл, перезапустить только
OpenDesign, затем отозвать прежний ключ через API Hub. Не переносить provider credentials
или ключи других приложений.

В существующем app-config выбирают `agentId: opencode`, а в
`agentModels.opencode.model` — `open-design-byok/main-dev`. После действительной настройки
runtime можно завершить native onboarding через штатный app-config. Сервер выбирает
транспорт и модель из installation config, не из клиентского run payload. И основной
агент, и его small-model операции используют тот же профиль; свободные провайдеры
OpenCode для этого запуска выключены.

## Транспорт и поставка

Docker-образ содержит официальный OpenCode `1.18.30`, с проверкой SHA-512 npm archive
для Linux x64/arm64 musl до распаковки. Новый отдельный сервис не создаётся.

Встроенный OpenCode plugin подключает fetch только к точному Hub Chat Completions
endpoint, запрещает redirects и выдаёт UUID `Idempotency-Key`. При сетевой ошибке,
обрыве либо незавершённом SSE прежний wire payload сохраняет UUID в пределах
текущего CLI invocation. Изменённый payload следующего tool step получает другой UUID;
после полностью прочитанного ответа с `[DONE]` новое действие получает новый UUID.
Перезапуск CLI является новым действием. Для managed Hub отключены все
автоматические перезапуски внутри run, включая восстановление native session.
Внутрипроцессные повторы транспорта сохраняются. При ошибке UI предупреждает,
что предыдущий запрос мог выполниться; историю/статус выясняют в Hub перед
явной новой попыткой. Standalone retry policy не изменяется.

Plugin обязателен для managed Hub run: ошибка загрузки прекращает запуск до inference.
Обычные standalone/OpenCode/BYOK настройки сохраняют прежнее поведение.

## Проверка готовности

`GET /api/pdlc/inference/status` защищён Central Auth и `open-design:read` для PAT.
Он возвращает только `state` и `model`, используя собственный ключ клиента для
`GET Hub /v1/models` с запретом redirect и timeout. Этот вызов требует `infer`,
возвращает только разрешённые опубликованные модели и не вызывает провайдера.
Состояния: `ready`, `not_configured`, `access_denied`, `model_unavailable`,
`hub_unavailable`. `ready` означает проверенный доступ к каталогу модели,
а не подтверждённую работоспособность provider inference.

UI проверяет доступ при открытии и по кнопке, daemon — перед каждым новым run.
При отказе новая генерация заблокирована, файлы доступны. Фонового polling нет.
В PDLC проверка OpenCode в настройках использует этот же безопасный путь,
а не отдельный пробный запуск CLI. `od status --json` сохраняет прежние поля
и дополнительно возвращает `inference`; токен задают через `PDLC_API_TOKEN`.

Проверять по отдельности: scoped transport tests, guard/typecheck, точный образ,
наличие CLI, разрешённый `GET /v1/models` с ключом OpenDesign, выбор runtime в UI,
затем реальную генерацию и появление файла. Тесты со своим upstream не доказывают
готовность модели или финансовую приёмку Hub. До публикации `main-dev` и допуска
client в Hub генерацию считать неподключённой; не подменять её `app-test`.

Настройку provider/model Hub выполняет его оператор. Поставка OpenDesign не меняет
Hub image, конфигурацию провайдера, другие clients и существующие данные.
